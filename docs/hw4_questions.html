MaxDiff Analysis of MSBA Class Preferences

Counts, MLE, and Bayesian estimation of the MNL model

Author

Chunjiang Liu

Published

May 28, 2026

Introduction

MaxDiff, also known as Best-Worst Scaling, is a survey method used to measure relative preferences among a set of items. Instead of asking respondents to rate every item on a numeric scale, MaxDiff presents a small subset of items at a time and asks respondents to choose the option they prefer most and the option they prefer least. In this assignment, each task shows four possible MSBA classes, and students repeatedly make best-worst choices across multiple tasks.

This format is useful because people are often better at making trade-offs than assigning consistent numerical ratings. A 1–10 rating scale can be difficult to interpret because different respondents may use the scale differently, and many items may receive similarly high scores. MaxDiff forces respondents to separate the options more clearly by identifying both a strongest and weakest preference within each choice set.

In this assignment, the ten items are the ten core MSBA classes at UCSD Rady. The goal is to estimate students’ relative preferences for these classes using three approaches. I begin with a simple counts analysis, comparing how often each class was selected as most preferred versus least preferred. I then estimate a multinomial logit model using maximum likelihood, which models the probability that a class is chosen based on its underlying utility. Finally, I estimate the same MNL model using a Bayesian approach with a Metropolis-Hastings sampler.

I expect the three methods to tell a broadly similar story about which classes are most and least preferred. However, they differ in what they provide analytically. The counts analysis gives a simple descriptive ranking, the maximum likelihood model estimates preference strength through utility parameters, and the Bayesian model adds a way to describe uncertainty around those estimates.

The Data

The raw dataset contains one row for each class option shown to a respondent in a MaxDiff task. Each row includes the respondent ID, the task number, the position of the option on the screen, the item number, and the response. A response value of 1 means the class was selected as the most preferred option, -1 means it was selected as the least preferred option, and 0 means the class was shown but not selected as either best or worst.

The class names are stored in a separate item-label file. I joined this file to the main survey data so that the numeric item IDs could be interpreted as actual MSBA class names.

Counts Analysis

A simple way to summarize the MaxDiff responses is to compare how often each class was selected as the most preferred option with how often it was selected as the least preferred option. For each class, I calculate the percentage of times it was chosen as best out of the number of times it was shown, then subtract the percentage of times it was chosen as worst. A higher score indicates a stronger positive preference, while a lower score indicates that the class was more often selected as least preferred.

\[ \text{score}_j = \text{best rate}_j - \text{worst rate}_j \]

This counts-based approach is easy to interpret and provides a useful first look at the preference ranking before fitting the multinomial logit model.

From MaxDiff Data to MNL Choices

The MaxDiff survey can be represented as a sequence of multinomial logit choice problems. In each task, a respondent sees four classes and makes two decisions. First, they choose the class they prefer most from the full set of four. Then, after the best item is removed, the worst choice can be treated as a second choice problem among the remaining three items, where lower-utility items are more likely to be selected.

The MNL model assigns each class \(j\) a utility coefficient \(\beta_j\). Higher values of \(\beta_j\) indicate stronger preference. If a task shows four classes \(\{a, b, c, d\}\), the probability that class \(b\) is selected as the best option is:

\[ P(\text{best} = b) = \frac{\exp(\beta_b)} {\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)} \]

The worst choice is modeled by flipping the sign of the utilities. After class \(b\) has been selected as best and removed from the set, the probability that class \(c\) is selected as worst from the remaining classes is:

\[ P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)} {\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)} \]

This means that each MaxDiff task provides two MNL choice observations: one best-choice observation from the full set of four classes and one worst-choice observation from the remaining three classes.

One normalization is needed because the MNL probabilities do not change if the same constant is added to every utility coefficient. Only relative utility differences are identified, not the absolute level of utility. Since there are 10 classes, only 9 independent coefficients can be estimated. I set \(\beta_1 = 0\) as the reference class and estimate the remaining coefficients relative to that class.

Before writing the likelihood function, I reshaped the cleaned MaxDiff data into one row per respondent-task. Each row stores the four classes shown in that task, the class selected as best, and the class selected as worst. This structure makes it easier to iterate over tasks when computing the MNL log-likelihood.

MNL via Maximum Likelihood

The counts analysis provides a useful descriptive ranking, but it does not explicitly model the choice process. The multinomial logit model does this by assigning each class a utility value and converting those utilities into choice probabilities. For each MaxDiff task, the likelihood has two parts: the probability of the observed best choice from the full set of four classes, and the probability of the observed worst choice from the remaining three classes after flipping the sign of the utilities.

For a task where \(j_b^*\) is the class selected as best and \(j_w^*\) is the class selected as worst, the log-likelihood is:

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[ \beta_{j_b^*} - \log \left( \sum_{j \in \text{shown}} \exp(\beta_j) \right) - \beta_{j_w^*} - \log \left( \sum_{j \in \text{shown} \setminus \{j_b^*\}} \exp(-\beta_j) \right) \right] \]

As before, I normalize the first class utility to zero by setting \(\beta_1 = 0\). The remaining nine utility coefficients are estimated by maximizing the log-likelihood.

Show code 
log_sum_exp <- function(x) {
  m <- max(x)
  m + log(sum(exp(x - m)))
}

ll_mnl <- function(beta_free, tasks) {
  beta <- c(0, beta_free)
  total_ll <- 0

  for (i in seq_len(nrow(tasks))) {
    shown <- tasks$shown_items[[i]]
    best <- tasks$best_item[i]
    worst <- tasks$worst_item[i]

    beta_shown <- beta[shown]

    best_ll <- beta[best] - log_sum_exp(beta_shown)

    remaining <- setdiff(shown, best)
    worst_ll <- -beta[worst] - log_sum_exp(-beta[remaining])

    total_ll <- total_ll + best_ll + worst_ll
  }

  total_ll
}

mle_out <- optim(
  par = rep(0, 9),
  fn = ll_mnl,
  tasks = mnl_tasks,
  method = "BFGS",
  hessian = TRUE,
  control = list(fnscale = -1, maxit = 1000)
)

The optimization converged successfully, so I use the estimated coefficients to calculate standard errors and shares of preference. The standard errors come from the inverse of the negative Hessian matrix. The shares of preference transform the utility estimates into a more interpretable scale: if all ten classes were shown together, the share represents the model-implied fraction of choices each class would receive.

\[ \hat{s}_j = \frac{\exp(\hat{\beta}_j)} {\sum_{k=1}^{10} \exp(\hat{\beta}_k)} \]

MNL via Bayesian Estimation

The maximum likelihood model provides point estimates and standard errors for the MNL utilities. A Bayesian version of the same model uses the same likelihood, but combines it with a prior distribution to form a posterior distribution over the utility coefficients. This allows us to summarize uncertainty directly from posterior draws.

The posterior distribution is proportional to the likelihood multiplied by the prior:

\[ \pi(\boldsymbol{\beta} \mid \boldsymbol{y}) \propto L(\boldsymbol{\beta}) \cdot \pi(\boldsymbol{\beta}) \]

I use a weakly informative normal prior for the nine free utility coefficients:

\[ \boldsymbol{\beta}_{2:10} \sim N(\boldsymbol{0}, 10I) \]

As in the maximum likelihood model, I set \(\beta_1 = 0\) for identification. I then use a random-walk Metropolis-Hastings sampler to draw from the posterior distribution.

Show code 
set.seed(495)

log_post_mnl <- function(beta_free, tasks) {
  ll_mnl(beta_free, tasks) +
    sum(dnorm(beta_free, mean = 0, sd = sqrt(10), log = TRUE))
}

mh_mnl <- function(beta0, n_iter, step, tasks) {
  k <- length(beta0)
  draws <- matrix(NA, nrow = n_iter, ncol = k)
  beta <- beta0
  lp <- log_post_mnl(beta, tasks)
  accept <- 0

  for (t in seq_len(n_iter)) {
    beta_star <- beta + rnorm(k, mean = 0, sd = step)
    lp_star <- log_post_mnl(beta_star, tasks)

    if (log(runif(1)) < lp_star - lp) {
      beta <- beta_star
      lp <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  list(
    draws = draws,
    accept_rate = accept / n_iter
  )
}

mh_fit <- mh_mnl(
  beta0 = mle_out$par,
  n_iter = 20000,
  step = 0.08,
  tasks = mnl_tasks
)

burn_in <- 5000

Discussion

Across all three methods, the main substantive finding is clear: students show the strongest preference for MGTA 495 Marketing Analytics. This class ranks first in the counts analysis, the maximum likelihood MNL model, and the Bayesian MNL model. MGTA 453 Business Analytics and MGTA 455 Customer Analytics also consistently rank near the top, which suggests that students in this sample are especially interested in applied analytics courses connected to marketing, business decision-making, and customer behavior. At the other end, MGTA 444 Analytics Consulting ranks last across all three methods, followed by MGTA 451 Marketing/Finance/Operations and MGTA 403 AI Math, Programming, and Analytics. I was a little surprised that the three rankings were completely identical, because I expected at least some small movement in the middle of the ranking after moving from counts to MNL and then to Bayesian estimation.

The biggest thing I learned from coding the likelihood myself is that the worst choice is not just another negative count. In the MNL setup, the best choice is modeled as a choice from the full set of four items, while the worst choice is modeled as a second choice from the remaining items after the best item is removed, with the utilities flipped. That detail helped me understand why MaxDiff data can be connected to a choice model rather than treated only as a simple ranking exercise.

Methodologically, I would use the three approaches for different purposes. The counts analysis is the easiest to explain and would work well for a quick dashboard or executive summary because it directly compares how often each class was picked best versus worst. The maximum likelihood MNL model is more rigorous because it models the choice process explicitly and estimates utility parameters and preference shares. This is helpful when I need a formal model and a single set of point estimates to report. The Bayesian MNL model is most useful when uncertainty matters. Because it produces posterior draws, it is straightforward to calculate credible intervals for derived quantities such as preference shares, and the same framework could be extended to simulations or individual-level preference models.

There are also important caveats. The data come from a self-selected sample of MSBA students, so the results should not be interpreted as the preference ranking for all future MSBA students. Students’ current standing in the program, prior coursework, career goals, and what they have heard from classmates may all affect their choices. Even though the MaxDiff design balances how often each class is shown, item order and survey context could still influence some responses.

If I had more time, I would explore whether preferences differ across student subgroups, such as students with more technical backgrounds versus students with more business-oriented backgrounds. I would also be interested in fitting a hierarchical Bayesian model, because the average ranking is useful, but it may hide meaningful differences in individual student preferences.
